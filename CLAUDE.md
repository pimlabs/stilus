# CLAUDE.md

## Project Overview

Bun monorepo. Two packages:
- `packages/core/` — `@stilus/core` engine (analysis, cleaning, chunking, profiles)
- `packages/mcp/` — `stilus-mcp` MCP server (7 tools, published to npm as `@pimlabs/stilus-mcp`)

Python prototype is archived (deleted from repo). All work happens in TypeScript.

## Commands

```bash
bun test                    # run all 50 tests (from repo root)
bun run bundle              # build dist/stilus-mcp (required before publish)
cd packages/mcp && bun run dev    # run MCP server locally (stdio)
cd packages/mcp && bun run publish:npm  # pack → publish tarball → git tag → push tag
```

## Release Flow

```bash
# 1. bump version in packages/mcp/package.json
# 2. commit + PR → merge to main
# 3. after merge, on main:
bun run bundle
cd packages/mcp && bun run publish:npm
```

`publish:npm` does: `npm pack → npm publish *.tgz → rm *.tgz → git tag vX.Y.Z → git push --tags`

## Critical: npm Publish Must Use Tarball

**Do NOT run `npm publish` directly from the workspace directory.**

npm workspace mode silently resolves bin entry paths from the workspace root instead of the package root, which causes the bin entry to be removed from the published package. `bunx @pimlabs/stilus-mcp` would silently not work.

Always use `bun run publish:npm` which packs first then publishes the tarball — npm ignores workspace mode when given a tarball path.

## Critical: Profile Static Imports

Built-in profiles are embedded as static JSON imports in `packages/core/src/config.ts`:

```typescript
import defaultJson from "../../../profiles/default.json";
import englishBookJson from "../../../profiles/english-book.json";
import indonesianBookJson from "../../../profiles/indonesian-book.json";
```

**Do not replace with filesystem reads.** `import.meta.url` and `import.meta.dir` do not resolve correctly in compiled Bun binaries. Static imports are the only approach that works.

Profile JSON source files live at `packages/core/profiles/`, not at repo root.

## Critical: `import.meta.dir` Banned

Do not use `import.meta.dir` anywhere in source code. It is Bun-specific and breaks in compiled binaries. Use static imports or `new URL("...", import.meta.url)` only when necessary.

## Critical: `@stilus/core` Is Not Published

`@stilus/core` is a workspace-only package (`workspace:*`). It is bundled into `stilus-mcp` via `bun build --bundle` at publish time. Do not publish it separately or change the dependency to a version range.

## Broken Line Detection — Regression Risk

Two places must stay in sync. If a line type is structural, it must be excluded in BOTH:

**`packages/core/src/analyzer.ts` — `isStructuralLine()`:**
- `isTableRow` (pipes or 3+ numbers)
- `isSectionHeading` (section + subsection patterns)
- `LIST_ITEM_PATTERN` — `/^(\s*[-*]|\s*\d+\.\s+)/` — added to fix false positives on numbered lists
- `figure_pattern`, `table_caption_pattern`, `footnote_pattern`

**`packages/core/src/cleaner.ts` — `mergeAndStructure()` `structural` variable:**
- `isHeading`, `isSectionHeading`, `isList`, `isUrl`, `isTableRow`
- `table_caption_pattern`, `figure_pattern`, `footnote_pattern`

Missing any one of these causes false positive broken line detections or incorrect paragraph merging. Both have previously had separate bugs.

## Test Fixture Constraint

`packages/core/data/example.md` must satisfy **exactly**:
- 72 words
- 2 broken lines
- 1 reference
- `word_delta = -2` after `mergeAndStructure` (two ` ,` patterns normalized by `normalizeText`)

Do not edit this file without updating the corresponding assertions in `packages/core/tests/analyzer.test.ts`.
